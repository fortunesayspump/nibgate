# Hub audit fixes, 10 November 2026

Both Hub networks use the same source changes. Backends, payout destinations,
wallet chain selection, private-worker verification and route ownership are unchanged.

## Implemented

- Fresh per-response script nonces and enforcing CSP in Next and its OpenNext adapter.
  No production `unsafe-inline`/`unsafe-eval` for scripts; WASM compilation remains
  allowed for confidential-worker verification. Existing inline **styles** remain
  allowed because the design and embedded wallet use them. Wallet/Reown, Arc RPC,
  media and the independently configured verifier origin have explicit allowances.
- `nosniff`, `X-Frame-Options: DENY`, `frame-ancestors 'none'` and popup-compatible
  `Cross-Origin-Opener-Policy: same-origin-allow-popups`.
- HTML renders dynamically with private/no-store cache headers. The outer Worker
  no longer serves cached information-page HTML: cached HTML cannot carry a fresh
  request nonce. Immutable static assets retain their existing delivery path.
  This sacrifices information-page prerendering and needs hosted latency/CPU checks.
- Request-derived canonical URLs use each network's fixed site origin and omit query
  parameters. Existing share-specific canonical metadata is preserved.
- Share labels associate with native controls, composite controls use fieldsets,
  rich-text/toolbars have accessible names, and upload dropzones are keyboard buttons.
- Widget footer uses a normal anchor. Worker GET/HEAD requests for `/widget.js`
  ignore RSC query/header inputs and return the same JavaScript asset.
- Explore distinguishes upstream failures from empty results and cancels stale
  searches. Pending Tips validates/normalizes domains before fetching either network,
  handles non-JSON/400/429/unavailable responses, and both loaders have request deadlines.
- Spreadsheet parsing is dynamically imported only for Excel whitelist imports.
  CSV import/export stays on its existing lightweight path.

## Validation

- Eight focused regression tests cover both outer Workers, CSP/header behavior,
  all five Share content types with paid whitelist controls, API errors and session/
  payment-proof transport. Fixtures never use real records or payments.
- Nineteen existing wallet-selection, network-routing and private-auth transport tests.
- Production Next build, TypeScript and actual locally bundled workerd/SQLite-DO
  rendering test: script/header nonce equality, canonical URLs, HTML/RSC and widget,
  plus synthetic session-cookie, authorized/unauthorized posting and 402/proof unlock.
- The inspected Share/Privacy HTML preloads only the required low-priority webpack
  runtime. The existing featured-image priority remains restricted to the first
  featured card. No speculative preload removal or blanket wallet deferral was made.

Run the focused tests after the normal workspace install and
`npm ci --prefix cloudflare/tooling --ignore-scripts --legacy-peer-deps`:

```
node --test tests/hub-audit.test.mjs
node --test packages/wallet/test/sign-in-selection.test.js packages/wallet/test/appkit-networks.test.js scripts/drnib-private-auth-transport.test.mjs scripts/drnib-private-auth-response.test.mjs
```

`tests/hub-audit-workerd.test.mjs` requires the actual dry-run outer bundle at
`.cloudflare-build/audit-outer` and matching assets at `frontend/.open-next/assets`.
It uses synthetic upstream services only; its session cookie and payment proof are
fixtures, not genuine provider authentication or financial authorization. To stage
this test after the normal configured Hub build:

```
node cloudflare/tooling/node_modules/wrangler/bin/wrangler.js deploy --dry-run --config .cloudflare-build/hub/testnet/wrangler.jsonc --outdir "$PWD/.cloudflare-build/audit-outer"
node --test tests/hub-audit-workerd.test.mjs
```

For a mainnet bundle use the mainnet staged config and `HUB_AUDIT_NETWORK=mainnet`.
Do not build both networks concurrently in one checkout.

## Remaining verification

Local tests do not establish live authenticated wallet, publishing or paid-unlock
success. Chrome verified the Share accessibility tree, article/photo controls,
paid price/payout names, wallet chooser opening without signing, and invalid Pending
Tips feedback. No CSP violations appeared in the captured console; Reown remote
configuration requests failed in the local environment, so provider authentication
is not established. Before promoting the enforcing CSP, exercise the pinned Dr. Nib
verifier and complete non-spending sign-in in the hosted environment, inspect CSP
violations, and check hosted render latency/CPU. Do not substitute a successful build or mocked proof for a financial test.
No real signature, payment, owner read or production write is part of these tests.
