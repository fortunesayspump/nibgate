# Private research

Dr. Nib's private architecture keeps document decryption and research orchestration inside a verified Phala confidential worker. The browser encrypts inputs before ordinary API ingress; saved projects, activity, reports and exports remain encrypted outside the worker. The familiar question → intake → plan → fund → research → report flow is retained.

## What private means

| Boundary | Behavior |
| --- | --- |
| Browser → ordinary Nibgate backend | Research content is encrypted; identity, timing, sizes and necessary financial metadata remain visible |
| Verified Phala worker | Decrypts authorized content in confidential memory, runs the agent and encrypts results/checkpoints |
| Primary inference | Separate verified Phala inference service; the CPU worker orchestrates rather than hosting the model weights |
| JEV decisions | Actual TypeSafe JEV through the pinned OpenRouter/TypeSafe ZDR route; selected judgment context is provider-visible |
| Authorized research fallback | Azure GPT-4o mini through OpenRouter ZDR; research context is provider-visible and disclosed before use |
| Public tools and payments | Only approved public arguments and required payment metadata leave their boundary; blockchain activity is public |

Zero-data-retention (ZDR) is a retention policy. It does not mean a provider never receives a prompt, and it is not hardware attestation. Dr. Nib must disclose JEV and hosted research processing instead of claiming that every model runs inside our worker. The ordinary backend must never silently substitute plaintext processing when private verification fails.
