# Retrieval bench

> **Processing scope:** this reference describes the ordinary research/API contract. Browser-encrypted state, verified worker key delivery and hosted-model boundaries are documented in [Privacy & confidential processing](/dr-nib/confidential). Ordinary API/MCP access is not a private-project decryption interface.

> **Availability:** This ordinary API is retired on both networks. Its testnet deployment was stopped on 26 Oct 2026, so the ordinary API/MCP examples below are historical reference and must not be used for new runs. Use [private Dr. Nib](/dr-nib/confidential) on [testnet](https://testnet.nibgate.xyz/dr-nib) or [mainnet](https://nibgate.xyz/dr-nib). Historical ordinary records are retained; direct legacy API reads need a reviewed restoration.

Where the agent's evidence comes from when it hasn't spent a cent: ten keyless indexes, optional configured SearXNG and keyed providers, model-driven web search over the run's own LLM key, document parsing for the files the web is actually made of, and honest reporting when a door is closed.

**Reference:** `dr-nib/backend/src/retrieval/`.

## Your own documents

At Configure, **Your sources** accepts PDF with selectable text, DOCX, XLSX, CSV, TXT, Markdown, and PNG/JPEG/WebP images with readable English text, plus readable public HTTPS links. Images are processed by local OCR; it may misread figures, handwriting and table structure, so check the extracted text against the original before approving research. Limits: five supplied sources per project, 2 MB per file, 20 megapixels per image, 100 PDF pages, ten workbook sheets, 5,000 data rows and 100 columns per sheet. Scanned PDFs still need OCR first. The UI shows upload progress, processing errors, extraction warnings, an extracted-text preview and an authenticated original download.

You can add or remove sources while preparing or reviewing a plan. Changing a planned source set discards that plan and returns you to Configure. Once an escrow job is opened or research starts, sources lock; end the run and create a new project for a different source set.

Originals use the private `nibgate-research` R2 bucket, separated by `testnet/` and `mainnet/` prefixes. They have no public bucket URL. Extracted text is also kept in the project database and sent to research AI providers when the research runs; private storage does not mean local-only AI processing. The [private processing path](/dr-nib/confidential) instead encrypts content in the browser before ordinary API ingress; it has a separate vault and key-delivery contract. Upload only documents you are authorized to process. Reports containing uploaded inputs use authenticated downloads rather than public R2 export links.

Choose **user sources only** to disable external search, API calls and creator tips. This mode requires at least one readable attachment. Changing sources after reviewing a plan invalidates it; sources freeze once execution starts. Starting a fresh run on the same topic does not automatically copy the files. Removing an input excludes it from research; originals remain in private storage for project history.

PDF evidence retains page markers; spreadsheet evidence retains sheet/row markers. CSV dates remain as entered instead of being converted to spreadsheet serial numbers. Numeric amount columns get deterministic decimal sums grouped by an explicit currency column, and by an explicit category column when present. Repeated full rows are flagged and remain in those sums. These sums are not a bank reconciliation, financial audit or currency conversion. Extraction over 100,000 characters is visibly truncated; report prompts use selected passages rather than guaranteeing exhaustive review of every row.

## Free indexes (no key, no signup)

The ordinary registry includes GDELT (paced), Wikipedia, OpenAlex, Semantic Scholar, Crossref, SEC EDGAR, Stack Exchange, Hacker News and Polymarket; arXiv joins when academic search is enabled. A self-hosted SearXNG joins when configured. Creator-preferred discovery additionally queries Hub metadata and Mwmbl, with relevance still taking precedence over creator preference. Tavily/Exa slots accept keys when configured. No separate search key is needed for model-driven search: the OpenRouter `web_search` server tool rides the existing LLM key — the model picks its own queries (Exa engine by default, a $0.007 search-cost estimate plus reported token usage) and only cited `url_citation` annotations become results, circuit-broken like every other provider. Queries are keyword-ified per provider; provider failures are tagged by name so the trail shows *which* source failed, not just that something did.

## Documents, not just pages

Fetched files are routed by magic bytes (not extensions) through real parsers, 10MB cap, single download:

| Format | Parser |
|---|---|
| PDF | text extraction |
| DOCX | document conversion |
| XLSX | spreadsheet parsing |
| PPTX | slide XML extraction |

## Bot-block honesty

When a site blocks machine reading, the run records `blocked-bot-check` with the provider named — reported, never worked around with evasion tricks. A thin-retrieval warning tells the data stage to reach for primary APIs, sandbox compute, or paid sources instead. A public URL named in the research brief also gets a free direct preview when search misses it, even if other free results are plentiful.

## How it feeds the loop

Search fans each sub-question across the bench; fetch opens ranked pages; Source selection narrows the candidates; JEV judges trust and evidence grade for the selected top sources. The depth controls how many sources are considered. Paid content that clears scoring joins on equal footing — paying never buys credibility. When the bench comes back thin, the loop's data stage escalates to direct tools. User-named public URLs are previewed separately; a 402 quote establishes price, network and asset, while only an approved purchase can supply the locked body as evidence. Payment proof fields are removed before the paid response reaches the research model. If another round receives a 402 for the same URL after purchase, the bought body remains the evidence for both writing and claim verification.

## Private retrieval boundary

The private worker reuses the retrieval registry through approved public tools rather than sending uploaded documents to the ordinary research service. External providers receive the approved query or exact URL; source-only mode blocks external discovery. The private terminal has no direct Internet access and reads approved cached responses, unlike the ordinary Railway sandbox's outbound-public networking. See [private tools](/dr-nib/confidential/models-tools).
