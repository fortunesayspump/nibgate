# Browser extension

The Nibgate extension lets you tip website pages with USDC. It shows an automatic tip button only on high-confidence creator content; version 1.2.0 also adds an explicit right-click action for any HTTP(S) page or linked page. Version 1.2.0 is live; the 1.2.1 source update is prepared for Chrome review. It is the human interface to [Nib Tips](/tipping): agents use the API route instead.

<Callout type="info">
**Live on the Chrome Web Store** ([install Nibgate](https://chromewebstore.google.com/detail/nibgate/hbinjoadmoahedigmjaldiclmakanknf)). Starts on Arc testnet with free faucet USDC.
</Callout>

## Install

- **Chrome Web Store**: [install Nibgate](https://chromewebstore.google.com/detail/nibgate/hbinjoadmoahedigmjaldiclmakanknf), pin it, done. Works in any Chromium browser (Chrome, Edge, Brave).
- **Sideload** (devs): build from source (`cd extension && npm install && npm run build`), then `chrome://extensions` → Developer mode → Load unpacked → select `dist/`.

After installing, pin it (puzzle-piece icon → pin **Nibgate**) and tap **Enable on all sites** on Home (or Settings → Tip button on web pages → Enable). Site access is optional and granted by you at runtime — install itself asks for almost nothing (see [Permissions](#permissions)).

## Your wallet

First open: **create** a wallet (recovery phrase shown once — write it down) or **import** one. The wallet is encrypted on-device (PBKDF2 + AES-256-GCM); keys live in the background worker's memory only and never touch web pages. Lock anytime from Settings → Security; reveal the recovery phrase there too (password required). If you forget the password, **Forgot password?** lets you restore from the phrase with a new password or clear the local wallet and start over.

Password inputs are concealed by default. The eye control works with mouse or keyboard, has a changing accessible label, and resets to concealed when you leave the screen; visibility is not persisted.

<Callout type="important">
Nibgate cannot recover a wallet without its recovery phrase. Clearing the local wallet removes its key and activity from this device; it does not move or erase on-chain funds. If you no longer have the phrase, clearing the wallet may permanently remove your access to those funds. There is no account or email reset.
</Callout>

## Tip any page (1.2.0)

Right-click an HTTP(S) page or link and choose **Tip this page** to open the extension amount, review, and approval window. This works on ordinary sites without creator classification or optional site access. Verified recipients use the existing settlement flow; unresolved URLs hold tips for the domain owner to verify and claim. Browser-internal URLs are unsupported. Version 1.2.0 is live on the Chrome Web Store.

The automatic **Tip the creator** button is limited to high-confidence posts on independent creator sites. Social-media routes—including individual X/Twitter posts and YouTube videos—plus Nibgate and loopback pages never auto-qualify. Both deterministic classification and the model fallback require post-level structural evidence, and SPA navigation removes a stale button immediately.

## Tipping on creator pages

1. Open an eligible creator article, tutorial, photo post, music recording, or video post. A **coffee icon** floats at the bottom right with a “Tip the creator” tooltip. A full **Tip the creator** button also appears at the end of the detected content. Use **×** to dismiss only the floating icon for the current page; the end-of-content button and right-click **Tip this page** action stay available. Both buttons open the same extension tip window for amounts, recipient review, and approval. (Nibgate's own sites and loopback development apps are excluded from automatic injection and assessment; they tip natively.)
2. Tap it: the Nibgate tip window opens. Pick $1 / $5 / $10 or custom, review exactly who gets paid and the fee, then **Approve** — nothing signs without your tap.
3. The receipt lands in **Activity**. Settled tips count in completed-tip totals; funded holds remain pending until claimed and are refundable while unclaimed.

### Fees

| Path | Fee |
|---|---|
| Creator resolved (settles instantly) | 1% |
| Creator unknown (held, claimed later) | 5% on claim |
| Refund to payer (held, unclaimed) | **0 — full amount, no fee** |

### Two outcomes, both safe

- **Creator resolved** — settles over x402 (direct transfer or Circle Gateway).
- **Creator unknown** — nothing pays blind. Funds wait in the domain's deterministic holding box (owner claims later); **refund yourself in full, anytime**, from Activity. Holdings never expire.

Full mechanics: [Nib Tips](/tipping).

## Also inside: send, receive, gateway

- **Receive**: address + QR per network. **Send**: USDC transfers with a fee estimate before confirm.
- **Gateway Deposit / Withdraw**: move USDC between wallet and Circle Gateway balance (used by paywalls and instant unlocks).

## For site owners — getting tipped

You don't need the extension and you don't need an account. If readers tip your pages before you've joined:

1. [Verify your site](/verify-site) to prove ownership.
2. Claim everything waiting in your domain's holding box in one go.
3. Optional: declare a recipient wallet on your page. Page-declared wallets still pass recipient checks; unresolved or unverified recipients can remain held. A right-click action does not inherit recipient metadata from a referring page.

Right-clicking the page targets its address; right-clicking a link targets the linked page. The approval window shows the exact target URL before payment.

## Permissions

| Permission | Why |
|---|---|
| `contextMenus` | Add the explicit Tip this page action for HTTP(S) pages and links (1.2.0) |
| `activeTab` | Read the current page only, to find tippable content |
| `scripting` | Register/remove the content script after optional site access changes |
| `storage` | Tip history + network preference, on-device |
| `alarms` and `idle` | Enforce wallet inactivity locking |
| `clipboardWrite` | Copy your wallet address or recovery phrase when you tap Copy |
| Optional site access | Granted by you at runtime so the button can appear on pages you visit |

No analytics, no remote code, no data sale. Full policy: [nibgate.xyz/extension-privacy](https://nibgate.xyz/extension-privacy).

## Troubleshooting

| Symptom | Fix |
|---|---|
| No button on a page | In 1.2.0, use **Tip this page** from the right-click menu. For the automatic creator button, reload the tab (especially right after enabling access); check the page isn't `*.nibgate.xyz` (excluded by design) or a non-content page (feeds, apps, logins stay button-free) |
| Button says funds will be held | Creator unresolved — expected. Tip holds safely, refundable in full |
| Wrong network showing | Tap the header pill; balances/history follow the active network |
| Popup closed mid-tip | Reopen from Activity — held and settled states are recoverable, nothing signs twice |
| Sideloaded build misbehaving after an edit | `npm run build`, then ↻ the card at `chrome://extensions`, then hard-refresh the page |

## FAQ

**Is this real money?** Only on mainnet, behind an explicit confirmation. Testnet is faucet play money.

**Can a site fake the tip button to steal?** No. Money UI renders only in the extension window, never in the page — and nothing signs without your Approve tap.

**Do tips expire?** Never. Unclaimed holdings sit until claimed or refunded.

**Which browsers?** Any Chromium (Chrome, Edge, Brave). Firefox/Safari are not packaged.

**I'm a developer — where's the code?** `extension/` in the [repo](https://github.com/fortunesayspump/nibgate): `README.md` is the full manual (architecture, resolution flow, JEV page model, build/dev/test, store notes), `docs/` holds the sideload, submission, and marker-convention guides. One paragraph version: content script (single trigger button, no secrets) → background worker (keys, signing, hub calls) → popup wallet shell + tip window (all money UI). No `confirm()`/`prompt()` anywhere; one build serves both networks.
