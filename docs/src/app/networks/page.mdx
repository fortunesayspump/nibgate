# Networks

Nibgate runs two parallel stacks on Arc. **Mainnet is the production surface** — real USDC, real creators. **Testnet mirrors it** for staging, development, and trying things with free faucet USDC. Identity syncs across stacks; money and content do not (details below).

## Hosts

| | Mainnet | Testnet |
|---|---|---|
| Hub site | `https://nibgate.xyz` | `https://testnet.nibgate.xyz` |
| Hub API | `https://api.nibgate.xyz` | `https://testnet-api.nibgate.xyz` |
| Subblogs | `https://{sub}.nibgate.xyz` | `https://{sub}.testnet.nibgate.xyz` |
| Subblogs API | `https://api-subblogs.nibgate.xyz` | `https://testnet-api-subblogs.nibgate.xyz` |
| Nibshare links | `https://nibgate.xyz/ns/{slug}` | `https://testnet.nibgate.xyz/ns/{slug}` |
| Docs (this site) | `https://docs.nibgate.xyz` | same (docs are network-agnostic) |

Subblog host conventions are `<name>.nibgate.xyz` and `<name>.testnet.nibgate.xyz`. Routing, database connections and identity synchronization must be configured on the corresponding stacks; a host convention alone does not deploy a second instance.

## What syncs across stacks

**Shared identity:** sites (domain, verification state, owner wallet, publisher profile, display metadata), user accounts (same wallet = same admin on both stacks — sign-in is find-or-create by wallet), and published editorial blog posts. Verify a custom domain once and both hubs agree; hosted `*.nibgate.xyz` subblogs stay network-pinned.

**Per-stack, never synced:** content catalogs, unlocks, payments, ratings, metrics, sessions. Every content/ledger row carries its hub-stamped `network` tag (`testnet` | `mainnet`), and receipts whose on-chain `chainId` attests the other stack are rejected at write time — testnet (valueless) money can never open mainnet (real-money) content.

## Selecting a network

**As an integrator** (creator site): set `NIBGATE_PAYMENT_NETWORK` to `eip155:5042` for production, `eip155:5042002` for staging. Point `NIBGATE_API_BASE` at the matching hub API. The [integration skill](/install-package) shows testnet values because testnet USDC is free — swap in the mainnet column above for production.

**As an operator** (Nibgate stacks): `NIBGATE_NETWORK=mainnet|testnet` on backends (default `testnet` — a missing var can never move real money), `NEXT_PUBLIC_NIBGATE_NETWORK` on frontends. Explicit per-value env vars (RPC URLs, contract addresses, origins) always override the network default. See the repo [README](https://github.com/fortunesayspump/nibgate#networks--deployments) for the deployment topology.

## For agents

The machine surfaces are per-stack: [discovery.md](https://nibgate.xyz/discovery.md) documents mainnet, `https://testnet.nibgate.xyz/discovery.md` documents testnet (endpoints, chain IDs, and Gateway hosts all follow the stack). The MCP server instructions likewise describe the network they run on.
