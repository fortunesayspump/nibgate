# Nibshare

Nibshare is Nibgate's hosted **quick-share** rail: connect a wallet, write content, set a USDC price, and get a short link at `https://nibgate.xyz/ns/<slug>`. No domain, widget, or site verification required — it is the on-ramp for "gate this snippet fast."

It runs on the same rails as the rest of Nibgate: x402 / USDC / Circle Gateway payments on Arc (`eip155:5042002`), AES-256-GCM encryption at rest, and a viewer/agent unlock flow. The difference: Nibgate hosts and serves everything, so there is no creator-owned domain behind it.

<Callout type="important">
Nibshare is a **separate, private rail** — it is never indexed in hub discovery, the public ledger, or on-chain reputation. Shares are ephemeral (expiry is optional but capped at 7 days) and have no creator-verified domain. Subblogs and creator sites are the indexed products; Nibshare is for quick gated sharing.
</Callout>

## When to use Nibshare vs a Subblog

| | Nibshare | Subblog |
|---|---|---|
| Domain required | No — short link `nibgate.xyz/ns/<slug>` | Yes — `*.nibgate.xyz` or your own |
| Indexed in discovery/ledger/reputation | No | Yes |
| Content lifetime | Optional expiry, capped at 7 days | Persistent |
| Access rail | x402 / Circle Gateway on Arc | x402 / Circle Gateway on Arc |
| Encryption at rest | All bodies + media | All bodies + media |
| Ownership check | Wallet session cookie | Site verification + admin wallet |

## Encryption at rest

Same policy as Subblogs: **no plaintext body or media ever touches object storage**. All cryptography comes from `@nibgate/sdk/server` (`packages/nibgate/src/server/crypto.js`) — the nibshare backend never implements its own crypto.

- Every share body and every uploaded media file is encrypted with **AES-256-GCM** (random 12-byte IV per call, 16-byte GCM auth tag).
- Keys are **server-side only** (`keyProvider: 'server'`, `decryptMode: 'server'`): the content key is generated by the backend, **wrapped with a backend-only KEK** (`NIBGATE_SHARE_KEY_SECRET`) before it is stored, and decryption happens per request. No key or ciphertext is ever vended to the browser.
- A modified blob fails the GCM auth-tag check before any plaintext is produced.

### Primitives

| Function | Input | Output |
|---|---|---|
| `generateContentKey()` | — | 32 random bytes (AES-256 key) |
| `encryptBytes(key, plaintext)` | key, buffer | `{ iv, tag, ciphertext }` |
| `packCipherBlob(enc)` | `{ iv, tag, ciphertext }` | single buffer `iv ‖ tag ‖ ciphertext` |
| `unpackCipherBlob(blob)` | blob | `{ iv, tag, ciphertext }` (rejects blobs < 28 bytes) |
| `decryptBytes(key, iv, tag, ciphertext)` | key + blob parts | plaintext buffer (GCM tag verified) |

Ciphertext blob layout:

```text
ciphertext blob (.bin, application/octet-stream)
┌──────────────┬──────────────────┬──────────────────────────────┐
│ iv (12 bytes)│ gcm tag (16 bytes)│ ciphertext (len(plaintext))  │
└──────────────┴──────────────────┴──────────────────────────────┘
```

### Upload & encrypt pipeline

Media uploads go through `POST /api/uploads/content?encrypted=1`. Images are optimized to WebP **before** encryption; the preview WebP is the only public plaintext byte for a share.

```mermaid

    E["Creator uploads media<br/>POST /api/uploads/content?encrypted=1 (multipart)"]
    O{"is image?"}
    P["processContentImage → auto-rotate, resize,<br/>WebP q90"]
    K["generateContentKey() → 32-byte random AES-256 key"]
    C["AES-256-GCM encryptBytes<br/>packCipherBlob → iv ‖ tag ‖ ciphertext"]
    U["putBlob .bin → R2<br/>nibshare/{userId}/enc/media/{ts}-{rand}.bin"]
    PV["processPreviewImage → small WebP<br/>nibshare/{userId}/public/preview/{ts}-{rand}.webp"]
    R["returns { storageRef, encryptedKey, contentType,<br/>name, size, previewUrl? }"]

    E --> O
    O -- yes --> P --> K
    O -- no (audio/video/document) --> K
    K --> C --> U --> R
    O -- yes --> PV
    PV --> R
```

### Storage layout

| Key | Content | Access |
|---|---|---|
| `nibshare/{id}/body.bin` | Ciphertext of the share body | private — read via server decrypt |
| `nibshare/{userId}/enc/media/{fileId}.bin` | Encrypted media item | private — read via server decrypt |
| `nibshare/{userId}/public/preview/{fileId}.webp` | Plaintext WebP preview (images only) | public CDN, immutable cache |

## Free vs paid reads

The difference is only at serve time, exactly like Subblogs:

- **Free shares** (`price = "0"`): `GET /api/nibshare/:slug/access` decrypts the body server-side and returns it with **no proof**. Anyone — human or agent — reads it.
- **Paid shares**: the same route relays the x402 Gateway challenge until payment. After USDC settles, the server checks the rules and returns the decrypted body scoped to that session.

```mermaid

    S{"share status?"}

    X["419 expired"]
    F{"price > 0?"}
    FR["200 free: decrypted body<br/>unlockProof: null"]

    PR2{"entitlement active?"}
    REV["403 revoked access"]
    G["402 + x402/Gateway challenge"]
    PAY["relay payment → rules check<br/>grant receipt + entitlement"]
    OK["200 paid: decrypted body<br/>payment + unlockProof + expiresInSeconds"]

    V --> A --> S
    S -- revoked --> R
    S -- active --> E
    E -- yes --> X
    E -- no --> F
    F -- no (free) --> FR
    F -- yes (paid) --> PR

    PR2 -- yes --> OK
    PR -- no --> G

```

## Payment proofs

After a paid unlock, the server returns an `unlockProof` that the viewer stores and replays on later reads (including media):

```text
{wallet}.{mac}   e.g. 0xabc...A7F3.5x2fYv...   (base64url)
```

`mac = HMAC-SHA256("nibshare:{shareId}:{wallet}")` keyed with a backend-only secret. The proof is sent back in the `x-nibgate-payment-proof` header (media also accepts `?proof=`). The server recomputes the MAC and looks up the wallet's entitlement — the proof only replays while that wallet's entitlement is `active`.

## Media streaming

Embedded assets stream through a decrypt proxy — the plaintext never lives at a stable public URL. Body references use `nibgate-embed://N` tokens; the viewer rewrites them to this route.

`GET /api/nibshare/:slug/media/:kind?index=N`

| `kind` | Resolves to |
|---|---|
| `photo` | `body.media[index]` (encrypted `{ storageRef, encryptedKey }`) |
| `music` | `body.audio` |
| `video` | `body.file` |
| `document` | `body.document` |

- Free shares stream with no proof.
- Paid shares require an active entitlement (proof header or `?proof=`), otherwise `403`.
- Responses are `Cache-Control: private, max-age=300`; documents/video also set `Content-Disposition` (`?download=1` → `attachment`, else `inline`).
- Legacy shares (pre-encryption, plaintext `url` fields) redirect to the stored URL.

```mermaid

    M["GET /api/nibshare/:slug/media/photo?index=N"]
    B["decrypt body → resolve media[index]"]
    H{"item has storageRef + encryptedKey?"}
    N["404 not found"]
    L{"legacy item.url?"}
    LG["302 redirect to legacy URL"]
    F{"share is paid?"}
    P{"valid proof → active entitlement?"}
    PF["403 must unlock"]
    G["getBlob(storageRef) → unpack → decryptBytes"]
    OK["200 plaintext · Content-Type + Cache-Control: private"]

    V --> M --> B --> H
    H -- no --> L

    L -- no --> N
    H -- yes --> F
    F -- no (free) --> G
    F -- yes --> P
    P -- no --> PF
    P -- yes --> G
    G --> OK
```

## Access rules

All checks run server-side at unlock/access time:

- `status` is `active` (revoked shares → `410 Gone`)
- not past `expiresAt` (→ `419`, "no new unlocks after expiry")
- payer wallet is in the `whitelist` when one is set (→ `403`)
- payment received for paid shares

**Expiry** stops *new* unlocks and sessions; it never revokes access already granted. Because the backend holds the key and decrypts per request, revoking a wallet's entitlement is a **hard** stop — the content stops being served to it. This is the hosted `server`-mode trade: clean revocation, but Nibgate serves every read. A future `client` mode (decentralized keys/storage) would relax that but cannot take a decrypted copy back.

```mermaid

    PA["paid: relay x402/Gateway<br/>payment must resolve payer wallet"]

    W{"payer in whitelist?"}
    WF["403 not whitelisted"]
    G["grant NibShareReceipt + NibShareEntitlement(active)"]

```

## Auth

Creating and managing shares uses a wallet session: a nonce-based **PersonalSignature** login establishes an `auth_session` cookie (30 days). Owner-only routes (revoke entitlement, revoke share, reslug, list mine) check that the session wallet owns the share. Viewing, paying, and media need no session.

| Scenario | Credential |
|---|---|
| Create / upload / manage | `auth_session` cookie (owner wallet) |
| View, meta, free read | none |
| Paid unlock | x402 payment (or stored proof) |
| Media replay | `x-nibgate-payment-proof` (or `?proof=`) |

## Limits

| Content | Cap | Enforcement |
|---|---|---|
| Share body (text/article) | 512 KB | `POST /api/nibshare` |
| Media per item | 30 MB | multer `fileSize` on `POST /api/uploads/content` |
| Expiry | optional, ≤ 1 week (168h) from now | `POST /api/nibshare` |


## API surface

Base URL: `https://api.nibgate.xyz`. Routes live under `/api/nibshare/*`, plus the media upload route under `/api/uploads`. Creating and managing shares uses the Nibgate wallet session cookie (`auth_session`, nonce-based PersonalSignature login, 30 days); owner-only routes also check that the session wallet owns the share.

| Endpoint | Purpose |
|---|---|
| `POST /api/uploads/content?encrypted=1` | Upload media — encrypted for gated shares (images are WebP-optimized before encryption) |
| `POST /api/nibshare` | Create a share (title + content + price; optional whitelist / expiry ≤ 7 days) |
| `GET /api/nibshare/:slug/meta` | Public metadata — title, price, cover, status. Never the body |
| `GET /api/nibshare/:slug/access` | The single read route: free shares open, paid shares relay the x402 challenge |
| `POST /api/nibshare/:slug/unlock` | Pay (or `walletAddress` for free) → receipt + entitlement → decrypted body |
| `GET /api/nibshare/:slug/media/:kind?index=N` | Stream one decrypted asset (`photo` / `music` / `video` / `document`) |
| `POST /api/nibshare/:slug/view` | Record a view (increments `viewCount`) |
| `POST /api/nibshare/:slug/entitlements/:wallet/revoke` | Owner: hard-stop one wallet in `server` mode |
| `DELETE /api/nibshare/:slug` | Owner: revoke the share and delete its R2 body blob |
| `POST /api/nibshare/:slug/reslug` | Owner: rotate the short-link slug |
| `GET /api/nibshare/mine` | Owner: list shares + unlock/view activity |

Paid responses carry an `unlockProof` (`{wallet}.{mac}`) the viewer replays on later reads and media. Share slugs are 8-char base58 short links. Full payload shapes, error codes, and status semantics live with the code in `backend/src/server/nibshare/API.md`.
