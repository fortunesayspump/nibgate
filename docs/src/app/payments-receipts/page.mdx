# Payments and receipts

Nibgate earnings are payment analytics, not withdrawals. Funds should flow through the creator site's configured receiver.

## Payment model

The creator package controls the receiver address. A creator can run multiple sites, and each site can use a different payment destination.

On a multipublisher platform, each resource can use the publisher wallet as `recipient`. The platform domain owns the widget token, but the publisher wallet owns attribution for content, receipts, earnings, and reputation.

<Callout type="important">
Nibgate does not need to custody funds to show earnings. It records payment events and receipt references after the creator site completes an unlock.
</Callout>

## MVP unlock model

The first package release should support one reliable path:

```txt
one resource -> one payment -> one verified unlock receipt -> one unlock token
```

Metered streaming, metered reading, passes, and agent quotas are future unlock strategies. They should still produce receipt events that can be indexed by Nibgate, but they are not required for the hackathon MVP.

## x402 gateway receipt

Use this when the unlock flow completes through a gateway-style x402 payment flow. Store the gateway receipt id or proof URL when available.

## Arc testnet receipt

Use this when the payment can link to an Arc testnet transaction hash or Arcscan URL.

## Event payload

Unlock completion events should include:

- `amount`
- `currency`
- `receiver`
- `recipient`
- `siteId`
- `publisherId` for platform content
- `publisherWallet` for platform content
- `contentId`
- `txHash` for chain transactions
- `paymentId` for gateway/provider records
- `receiptUrl` when the provider returns a real receipt URL
- `chainExplorerUrl` when available
- `paidAt`

## Earnings dashboard

The dashboard should group earnings by site, receiver, content, currency, and time range. Clicking a receipt should open the source transaction or gateway receipt when available.

For platform publishers, the creator dashboard should also group earnings by publisher identity, for example `@alice on platform.com`. The wallet Alice uses on the platform should match the wallet she uses to sign into Nibgate.
