# Quick start

Connect a wallet, register a site, paste the widget, install the package, and start sending content plus unlock events to Nibgate.

<Callout type="important">
The widget verifies the website. The package powers gating, payments, content metadata, unlock events, and receipt reporting.
</Callout>

<Callout type="info">
If you publish on a multipublisher platform, you do not add the platform domain as your own site. The platform verifies the domain once, and you connect the same wallet on the platform and on Nibgate so your publisher route, content, and metrics can attach to your account.
</Callout>

<Steps>
### Connect wallet

Your wallet is the creator identity. It owns the profile, connected sites, content dashboard, analytics, and earnings views.

### Register your site

Add the exact origin where protected content lives, for example `https://creator.com`. Nibgate returns a `siteId` and verification token.

Only register domains you control. On a platform like `platform.com/@alice`, the platform owner registers `platform.com`; Alice claims a publisher identity with her wallet.

### Paste the widget

The widget verifies ownership and streams page activity from the verified domain.

```html
<script async src="https://nibgate.xyz/widget.js"
  data-nibgate-site="site_..."
  data-nibgate-token="ngv_..."
  data-nibgate-api="https://api.nibgate.xyz">
</script>
```

### Install the package

The package belongs in the creator app. It controls gating, pricing, content metadata, unlock events, and receipt reporting.

```bash
npm install nibgate
```

### Publish content metadata

Send public metadata for each paid resource. Keep the protected content itself on your own domain.

```ts
import { gate } from 'nibgate'

const guide = gate({
  id: 'premium-guide',
  title: 'Premium Guide',
  type: 'article',
  price: '0.01',
  path: '/premium-guide',
  access: {
    humans: 'paid',
    agents: 'paid'
  },
  unlock: {
    mode: 'one_time'
  }
})

guide.content()
guide.view()
```

### Check the dashboard

Use Sites, Contents, Analytics, and Earnings to confirm the setup is active.

For platform publishers, the dashboard should show the claimed route under Publisher Identities, for example `@alice on platform.com`, and scope content, metrics, earnings, and reputation to the wallet used on both the platform and Nibgate.
</Steps>

## MVP unlock model

For the first stable package, Nibgate should ship one unlock path well:

```txt
pay once -> verify receipt/proof -> issue unlock token -> serve content -> report receipt
```

Future package versions can add metered streaming, metered reading, time passes, and agent quotas through the same `unlock` policy field.
