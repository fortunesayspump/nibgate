# Reputation

Nibgate reputation should be grounded in verified content interactions. A feedback signal is stronger when it is tied to a real view, unlock, payment receipt, citation, or agent usage event.

<Callout type="warning">
Open reputation systems can become noisy if anyone can rate anything. Nibgate should weight feedback based on verified interaction history, source quality, and abuse resistance.
</Callout>

## Reputation hierarchy

Content reputation is the primary score. A creator should not get trust points in the abstract; their reputation should be earned from the quality, accuracy, unlock history, receipts, and feedback attached to actual resources.

In public content cards, content reputation can be shown as a familiar 0-5 star rating. Under the hood, that rating can still be computed from verified views, unlocks, payment receipts, feedback, citations, and freshness.

Site reputation and creator reputation then roll up from content reputation.

```txt
Content reputation
  -> contributes to site reputation
  -> contributes to creator reputation
```

That means a creator can have a strong overall reputation while a specific new piece is still unproven. It also means one excellent piece can start improving a newer creator's reputation without pretending the whole account is already fully trusted.

## Content reputation

Content reputation should answer whether a resource is useful, current, accurately described, and worth unlocking.

It can include:

- verified views
- content views
- unlock attempts
- completed unlocks
- payment receipts
- time spent
- repeat visitors
- citations
- human feedback
- agent feedback
- stale or misleading metadata penalties

## Site reputation

A site can have its own health: verified, stale, removed, frequently updated, high conversion, or repeatedly disputed.

Site reputation should be a weighted rollup from the content hosted on that domain plus source health signals like active widget checks, valid ownership, payment consistency, and content freshness.

## Creator reputation

A creator can build reputation across multiple sites. Creator reputation should be a weighted rollup from content reputation and site reputation, not a standalone vanity score.

Creator reputation should be a 1-100 score attached to the creator wallet/account that owns verified sites. It can include consistency over time, number of verified useful resources, unlock success, buyer/agent feedback, and penalties from broken, removed, or misleading content.

## Agent feedback

Agents can submit feedback after interacting with content. Stronger feedback can come from agents that actually unlocked, cited, summarized, or used the content in a workflow.

## Signal examples

- Verified unlock completed.
- Receipt exists and links to a payment proof.
- User or agent spent meaningful time with the content.
- Content was cited or reused in a workflow.
- Feedback came from a wallet or agent with prior trusted activity.
- Content remained available and matched its metadata.

## Ranking principle

Reputation should not be a vanity score. It should help humans and agents discover content that is verified, useful, current, and fairly represented.
