# Capabilities and scope

Nibgate combines creator-owned content integration, hosted publishing, public discovery and private research.

## Implemented capabilities

- **Creator SDK:** browser metadata/events, server access checks, Circle Gateway and direct-USDC payment helpers, manifests and rating helpers.
- **Wallet integration:** shared wallet connection, SIWE sign-in, Gateway deposit/checkout and recovery of submitted payment proofs without creating a second payment.
- **Subblogs:** hosted articles, galleries, audio, uploaded video and documents; server-side encryption at rest; public, paid and invite-only access.
- **Nibshare:** expiring, server-encrypted shares with owner analytics and link-based access. Content is not indexed in public discovery.
- **Discovery and reputation:** public metadata, receipts, accepted rating proofs and content/site/creator rankings.
- **Dr. Nib:** browser-encrypted private projects, verified Phala orchestration, disclosed JEV and authorized hosted-model processing, bounded tools, checkpoint recovery and escrow receipts. See [private research](/dr-nib/confidential).

## Integration boundaries

`one_time` is the implemented unlock mode. The resource schema also names metered reading/streaming, time passes and agent quotas; those names do not add enforcement automatically. A creator integration must keep paid payloads behind server-side checks and supply its own protected storage/rendering where needed.

The SDK is framework-agnostic, but listing a CMS integration pattern does not mean a maintained native plugin exists. Payment availability depends on the configured network, contracts and providers. Hosted access revocation changes future reads; it cannot retract a downloaded copy or reverse a completed transfer.
