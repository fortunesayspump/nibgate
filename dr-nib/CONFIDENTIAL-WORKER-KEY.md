# Bounded client-held private worker key

For the first full-worker slice, the browser creates one fresh 32-byte random state key for each private run. It keeps the key in tab memory. After a fresh, independently verified attested guest session and recipient-key possession check, it HPKE-encrypts a second source-purpose envelope to that guest's ephemeral public key. The encrypted UTF-8 payload has exactly `format: "drnib-worker-key-v1"`, the verified session UUID, and a canonical base64 `stateKeyBase64`. Its AAD binds authenticated tenant, run, unique object, revision, purpose and recipient key. Railway relays only ciphertext and cannot derive the state key. The measured guest must recheck tenant/run ownership and classification before opening it.

`private-worker-key.js` unwraps the key only inside an awaited measured-guest job callback. HKDF-SHA256 derives distinct 32-byte AES-GCM keys for state, worker-source, claim, decision, step, report and event, domain-separated by tenant/run/purpose. These feed `PrivateWorkerStore` and `PrivateWorkerEventPort`. It best-effort wipes the opened bytes and base key and revokes **new derivations** when the job returns. JavaScript cannot guarantee erasure of decoded strings or already-returned subkeys. The measured job must not log or retain them. This is a local key-bridge contract, not evidence that Phala attestation, browser code integrity, guest routing or inference are live. One-use session enforcement, owner authentication and actual attestation remain caller obligations; the helper checks their supplied identity bindings but cannot establish them independently.

`private-plan-session.js` is a callable measured-guest composition: it decrypts the existing bounded source-file/text payload, rejects truncated parses, initializes the encrypted state and one user-uploaded source atomically with fixed `planning` status, and calls the real Dr. Nib planning prompt through the injected attested AI port. Its source-only composition then advances to fixed `running`, runs the real short Dr. Nib writer, and atomically stores the external HPKE report and fixed `complete` status. Synthetic integration tests decrypt that browser report and find the late-source canary, while captured Prisma-shaped writes and fixed receipt contain none. This slice requests 300 report words to fit the pinned private AI output-token ceiling; it is not the legacy 1,200–12,000-word report workflow. A separate `full-execute` route now journals both encrypted source and key envelopes before the model, but is **off by default** and awaits migration, cost admission, hardware and live-path tests. Other research stages remain incomplete.

There is deliberately **no server-held recovery key**. A CVM restart destroys the in-memory state key. A browser retaining the key could, in principle, rewrap it to a fresh verified guest and decrypt the existing checkpoints, but the current guest only opens new sessions for `draft` runs and the journal parks interrupted paid calls as `uncertain`. **Functional restart/resume is not implemented.** If the browser key is gone, checkpoints are unreadable; the user needs a new run/re-upload. No ordinary-provider, deterministic dstack KMS key, Railway escrow key, or plaintext fallback is allowed. Idle shutdown must wait for active jobs to drain. An interrupted paid provider call cannot be blindly replayed.

Before live release: apply and rehearse the additive schema, enable the separate full route only with reviewed cost controls, finish the remaining measured-worker stages, run Node 22 browser/guest interoperability and real Phala restart tests with a retained client key, and exercise wrong tenant, deleted run, changed measurement, stale session, lost key and timeout recovery. The browser must disclose that closing the tab loses its key in this first version.
