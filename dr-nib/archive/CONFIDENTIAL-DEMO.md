# Dr. Nib confidential source demo: implementation status

**Hardware update, 2026-10-16:** A credential-free diagnostic guest on production Phala dstack 0.6.1 returned fresh V1 session evidence. The signed session binding passed Intel QVL and the pinned official full dstack verifier; the temporary CVM was deleted. This verifies the diagnostic attestation path only. The normal guest, broker, browser pin, database, AI channel/receipt, and encrypted source workflow have not passed together on hardware. Private source and paid AI modes remain off.

This is a bounded, source-only path using Dr. Nib's existing `parseSource` and `reportMessages`. It is not the complete `runPlan`/`runExecute` engine or a verified production operator-blind deployment. Existing research, payments, JEV, exports and subblogs remain on their current paths; confidential rows are denied in conventional worker/routes.

## Data flow

1. A same-origin broker authenticates the Nibgate account and creates a draft `ResearchRun` with no question, filename, source text or result in its ordinary database fields. That route is closed unless a private CVM reports job readiness; private mode is off by default. The broker issues short-lived, scope/run/tenant-bound EdDSA JWT capabilities to the guest and forwards ciphertext, proof and public evidence only. The guest never receives the hub cookie. Actual capability key provisioning is not done.
2. The measured Phala guest makes an ephemeral P-256 HPKE key and requests **v1 MessagePack** evidence through `/v1/Attest` on `/var/run/dstack.sock`, binding a fresh browser nonce, session ID and public key. The published dstack SDK 0.5.8 `attest()` uses legacy v0, so this path calls v1 explicitly. The browser must verify the quote and independently approved release/boot policy, then challenge the guest to prove HPKE private-key possession before encrypting any document or question. A mutable operator-served web client remains a trust limitation unless its verifier/code/policy are independently pinned.
3. The browser keeps its own ephemeral result key and HPKE-seals either supplied text or file bytes with question and result public key. Nibgate forwards ciphertext. The guest decrypts, runs the existing parser for PDF/DOCX/XLSX/CSV/TXT/MD/images (raw file <=2 MiB), and splits up to 100,000 extracted characters into <=1,700-character passages before calling Dr. Nib's existing report prompt. A late-page synthetic canary test ensures the existing 1,800-character-per-source prompt excerpt limit does not silently discard later pages. If `parseSource` truncates, the encrypted report explicitly states that only the first 100,000 characters were analyzed. This still needs quality and latency evaluation, particularly for bank statements.
4. The guest may call only the pinned Phala ACI transport, with `aci_verified`, ZDR routing, no fallback, a fixed model, a 150,000-character prompt ceiling and 1,200-token output ceiling. The SDK-pinned TLS channel and signed receipt are checked against the actual request digest, model and upstream session. The generated report is HPKE-sealed to the browser key carried in the encrypted input and saved as ciphertext in the existing `ResearchReport` table; the browser decrypts and renders without remote images. If the browser tab/key is lost, this demo requires reupload. No operator-held recovery key is claimed.

## Files and local checks

- Guest: `backend/src/privacy/private-guest-main.js`, `private-guest-http.js`, `guest-session.js`, `private-demo.js`, `private-repository.js`, `phala-quote.js`, `phala-aci-adapter.js`, `phala-ai-port.js`, `source-hpke.js`. `private-guest.Dockerfile` has a Dockerfile-specific context allowlist. `DRNIB_PRIVATE_DIAGNOSTIC_ONLY=true` exposes public health and nonce-bound attestation **without** DB, broker or AI credentials and refuses private jobs. Normal mode requires all dependencies and, by default, does not expose the public diagnostic quote endpoint. The separate `DRNIB_PRIVATE_REVIEW_ATTESTATION_ENABLED=true` flag may expose the same nonsecret, rate-limited, nonce-bound `/v1/private/attestation` endpoint in normal mode **only** so a reviewer can run the pinned full dstack verifier against that exact instance during the deployment review window; it must be removed or set false for the sustained release, and it never exposes private source, keys or jobs.
- Ordinary API: `private-runs.js` and `private-broker.js` are mounted under `/v1/private`. Missing configuration, disabled flag or guest `privateReady:false` closes creation and forwarding. The existing conventional worker still refuses confidential rows. A subsequent cloud follow-up adds an encrypted-request job journal and authenticated fixed-status recovery route; see `CONFIDENTIAL-JOB-RECOVERY.md`. It is not in the frozen 18:36 Mac baseline and needs real Postgres/crash tests before deployment.
- `node --test dr-nib/backend/src/privacy/*.test.mjs` is the synthetic/unit contract suite. The cloud Node 24 sandbox skipped two Unix-socket transport tests because AF_UNIX listening was prohibited; those two tests and the local diagnostic HTTP fixture passed on the Mac with socket permission. Full Vitest/Postgres and normal-mode guest/broker/browser checks remain separate. No real private records or paid inference were used.

## Release blockers

- A diagnostic Docker image was built on the Mac and pinned by digest for the deleted CVM; normal-mode guest image and release controls require their own review. The Dockerfile's mutable base image tag must be pinned to an independently reviewed digest before a confidentiality claim. Phala compose/app/OS/instance identity, disabled SSH/debug/plaintext logs, network egress policy and code-update governance must be reviewed for each real private-data release. The credential-free diagnostic VM did not perform these remaining checks.
- `@phala/aci-verifier` 0.7.3 requires bare lowercase 64-hex `aci_session_ids`; a credential-free read of Phala's live public session endpoint found exactly that format, and hashing the full public artifact matched its ID. Older gateway documentation shows `as_`-prefixed IDs for a different subset-hash scheme; never strip or guess a prefix. This resolves the listed-session compatibility question, but a live pinned-channel handshake and request/receipt test still have not passed in the target runtime. The SDK alone also does not establish full TCB, boot/KMS custody policy or ZDR cryptographic non-retention.
- A real browser verifier needs an independently trusted pin manifest, successful current collateral/QVL verification, a live proof-of-possession test and a non-mutable delivery/update policy. Verify no plaintext canary in Postgres, R2, Redis, queues, logs/traces, tools, model requests to unapproved providers, report/export routes or error responses. Full Dr. Nib worker migration, JEV decision-quality comparison, encrypted checkpoints/exports, multi-source continuity and restart/recovery are still required for the full product claim.
- User's Phala ceiling is USD 5 total per month for compute, retained disk and AI. The on-demand controller currently has only a soft admission timer; it is not a provider billing hard stop. A stopped VM cannot wake itself. The ordinary broker needs an authorized Phala start/stop controller plus verified spend guard before an automatic on-contact experience is enabled.
