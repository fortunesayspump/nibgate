# Dr. Nib full-worker confidentiality migration

> Historical design, archived 18 October 2026. Superseded by [the current privacy plan](../privacy/PLAN.md). Preserve as research history; do not use as a deployment runbook or current status.

Status: implementation map against the existing worker, not a claim that the full worker is private or deployed. The bounded private document flow and the legacy-path denial gate are separate. Do not turn the legacy `run.plan` / `run.execute` handlers on for confidential rows until every gate below passes.

## Execution boundary and operator view

The browser encrypts the question, source bytes and an ephemeral report-recipient key to a fresh Phala CVM session only after independent verification of its pinned code/boot policy, freshness and recipient-key possession. The CVM decrypts, runs the existing Dr. Nib planning/retrieval/analysis/writing logic through private ports, and stores sealed checkpoints and HPKE report envelopes. Railway retains authenticated account ownership, scheduling, ciphertext transport, fixed status, accounting and an on-demand CVM controller. It never receives the document key. Phala Cloud operators and any approved inference processor remain separate trust considerations; code/compose updates, SSH/debug/logs, KMS policy and mutable web-client delivery must be independently controlled before making a strong operator-blind promise.

Public search is not magically private: exact query strings, URL paths, HTTP bodies and timing are disclosed to their target search/extraction/API providers. The browser must offer “my sources only” as the default for private files; optional web research requires explicit per-run disclosure/consent. `run_code` can send private input to its sandbox provider and is disabled until a separately attested, egress-restricted compute boundary exists. Tips, paid unlocks, x402, ratings and escrow need a separate consent/signing design; no agent wallet key enters the CVM in the first full-worker release.

The Prisma schema also has plaintext-bearing `ResearchRun.title`, `description`, `brief`, `plan`, `pendingQuestion`, `pendingGuidance`, `metadata`; `ResearchSource.url/title/domain`; `ResearchClaim.text/passages`; `ResearchDecision.prompt/question/criteria/answer/output`; `ResearchStep.input/output`; `ResearchReport.markdown/citations`; `ResearchEvent.payload`; `ResearchExport.r2Key`; `IdempotencyKey.response`; and global `AgentLesson.task/lesson/stopReason` with an on-disk fallback. A private row must never put document-derived prose into any of those ordinary fields. Column names `status`, `kind`, timestamps, monetary amounts and run/tenant IDs reveal metadata and must be disclosed. A sealed stage row alone does not cover the remaining models.

## Repository port, without a second research engine

Extract `worker.js` stage functions into an injected `WorkerContext` built at the entrypoint. Preserve plan/search/fetch/data/score/review/write sequence and current depth, metering and idempotency semantics. The context supplies: `store.loadRunState`, `store.claimStage`, `store.finishStage`, `store.readSteps`, `store.upsertSources`, `store.writeDecision`, `store.writeClaims`, `store.writeReport`, `store.readReport`; `events.emitSafe` and `events.emitSealed`; `ai.generate/verify`; `judge.sourceBatch/choice`; `tools.run`; `billing.meter`; and `clock`. Legacy context wraps today's Prisma/JEV/OpenRouter implementations; private context is constructed only in measured guest after fresh attestation/key release. A private context must have no reference to ordinary `recordEvent`, `publish`, conventional `runTool`, ordinary JEV, normal model provider, raw Prisma models or sandbox/payment implementations.

For the private context, envelope AAD includes tenant ID, run ID, object ID, revision and purpose. Plaintext is serialized inside the guest with fixed safe error codes. Keep active lease/status/attempt in clear for recovery; put result, `why`, URLs and provider diagnostics in sealed `ResearchStep.output`. Recheck the immutable privacy classification and owner inside transactions, not only at entry. Pending guidance/questions and plan remain inside a sealed run-state object, with a public fixed status pointer. Source/claim/decision rows require a schema migration or replacement by sealed per-kind objects; do not write encrypted JSON into plaintext `url`/`text` and assume all readers will handle it. Schema migration must be additive, legacy-preserving, and separately approved/rehearsed; current bounded demo avoids it.

## Decision handling and quality

`runSourceBatch` needs title, URL, excerpt and topic for substantive trust judgments; a coarse feature set cannot replicate that judgment. Route substantive source/claim checks through an independently verified confidential model. `runChoice` for “continue or write” may use only fixed enums from `decision-minimization.js`, after protected analysis computes them, with explicit disclosure that even those derived flags leak some information; hard depth/budget limits stay local. If the approved JEV zero-retention route is absent or output invalid, park, never swap to normal Hub. Compare ordinary and private paths on consented public/synthetic cases: source grading, exact amounts/dates, report citations, coverage, claim verification, latency and metered cost. No claim of equal quality before a paired evaluation.

## Release sequence and negative tests

1. Complete the bounded source-only CVM path and independently verify real V1 attestation, pinned boot/compose/app/KMS, key possession, live AI channel/receipt, clean Node 22 build, Docker build, browser QVL, and synthetic canary checks across database/R2/queue/logs/HTTP. Paid/live release is still blocked until provider compatibility and hard cost controls are resolved.
2. Add a private `WorkerContext` in the guest and migrate plan then each stage incrementally behind a test-only runner. At each stage, inject a canary into input, provider exceptions, tool result, URL, guidance and model output and assert it is absent from all ordinary sinks. Resume from a sealed checkpoint after a simulated crash and prove no double spend.
3. Replace direct Prisma reads/writes in `verify`, memory, evidence search, source selection, event feed, report/export and all route/MCP/budget/settlement paths; run source-wide grep plus runtime DB/R2/queue/log/trace canary capture. Disable any path that is not migrated; preserve legacy rows and behavior.
4. Independently authorize and test external search disclosure, sandbox, payments and cross-run memory one capability at a time. Finally test concurrent/idle CVM wake/shutdown, restarts, lost browser tab/session, unreadable key, stale/changed measurement, malformed envelopes, replay, wrong tenant, downgrade/unknown mode, provider outage, signed receipt mismatch and operator-controlled website/code updates. Every failure must be a fixed error, a parked job, or an encrypted recoverable result; never plaintext fallback.

The current bounded `/execute` call is synchronous. A broker/client timeout after the guest sealed version 1 can lose the report ID, while a retry hits the `(runId, version)` uniqueness rule. Add a ciphertext-only idempotent job receipt and authenticated status/report lookup keyed to the same request before claiming reliable retries; never return an existing report for a different ciphertext/browser recipient.

This document is a code map, not evidence of production confidentiality. The full-engine adapter, schema changes, live hardware run and paid-provider tests remain open.
