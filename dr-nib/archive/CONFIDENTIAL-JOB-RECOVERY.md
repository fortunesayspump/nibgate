# Private execute recovery follow-up

Status: cloud follow-up patch after the frozen 18:36 diagnostic/document snapshot. Local synthetic tests pass; it has not been applied to the Mac clean-build baseline or tested with Postgres, Phala hardware or paid inference.

`private-execute-journal.js` records a fixed, encrypted-request SHA-256 fingerprint in one `ResearchStep` row of kind `private-execute` under the existing run-scoped Postgres advisory transaction lock **before** the measured guest calls the model. It never stores a document, prompt, model output or decrypt key in that row. The first exact ciphertext request can start; a concurrent/retried exact request returns processing or its prior report ID; a different ciphertext on that run returns fixed 409. The row is owner and confidential-classification checked again inside the transaction.

The model writes the HPKE report first, then the journal marks the row complete with only its report UUID. If the HTTP response is lost after the report write, GET `/v1/private/runs/:runId/job` (same-origin browser path `/drnib-api/v1/private/runs/:runId/job`) atomically reconciles a valid sealed version-1 report and returns `{state:'complete',reportId}`. The GET is authenticated to the existing Nibgate owner at the broker, then to a 45-second `jobs:read` capability at the guest. Other fixed states are `not_started`, `processing` and `uncertain`; no document-derived error text is returned. POST execute retains the existing successful `{id,version:1,encrypted:true}` response and may return 202 `{state:'processing'|'uncertain',runId}`.

The separate, default-off `/sessions/:id/full-execute` path fingerprints **both** the source and client-held worker-key HPKE envelopes in one claim before plan or write makes a paid call. Its report ID is the run UUID. The measured store atomically commits the external ciphertext report with fixed `complete` status. Journal recovery only accepts that report after the run is complete, then returns the stable ID without repeating model work. The bounded document path above remains compatible and continues its original report-first reconciliation. Full mode requires the additive `PrivateWorkerObject` migration and separate broker/guest readiness flags; these are not enabled by the diagnostic/document snapshot.

An `uncertain` job is **never** automatically re-run: a guest death after a paid model request but before a report save cannot prove the model was not charged. This design prevents a blind duplicate charge; it does not guarantee exactly-once billing, immediate recovery or availability. A model operation exceeding the five-minute lease appears uncertain until it completes. `not_started` means no durable claim exists, but the current guest destroys its one-use session on any execute exit, including an early failure; it does **not** imply the original sealed envelope/session is reusable. An explicit retry needs fresh attestation, proof of possession and re-sealing retained local input/key to a new recipient, or a new run/re-upload if those are lost. The UI must retain the run ID and browser report key in memory, strictly validate all status responses, poll for bounded time, then offer manual status check. No operator-held recovery key is introduced.

An interrupted **full** job currently cannot resume from sealed plan/write checkpoints: session creation accepts only `draft` runs, and a post-claim uncertain job is never re-dispatched automatically. A browser-retained state key makes those checkpoints cryptographically readable after a future verified rewrap flow, but no such resume API exists yet. Report `uncertain` and require an explicit recovery design; never imply that an arbitrary fresh session can restart the paid job.

Before release: test against real Postgres transaction advisory locks and concurrent broker requests, lost-response timing at each crash point, strict 409 propagation, an active model call longer than the lease, stale/malicious report rows, cross-tenant GET and source digest mismatch, browser polling and Mac Node 22 clean build. Instrument one harmless paid inference to confirm the journal claim exists before any request and only one model call occurs under concurrent retries. The existing frozen snapshot remains separate until these checks pass.
